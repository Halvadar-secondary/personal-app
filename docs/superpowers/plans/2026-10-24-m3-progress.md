# M3 Progress and Repeating Tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Completing tasks visibly grows each area's level, XP bar and streak, completed achievements show as trophies, and daily-practice tasks can be set to repeat and checked off each day. An Active page gathers today's practice, what's due soon and every active achievement. A Settings page sets the owner's time zone and week start.

**Architecture:**
- **Pure logic in `src/lib`:**
  - `levels.ts` for the level curve, `streaks.ts` for the current streak, `recurrence.ts` for occurrences, presets and the 4-week strip, and `agenda.ts` for "up next".
  - Everything works on `YYYY-MM-DD` date strings with UTC calendar arithmetic, so daylight saving can't shift a day. The only instant → date step is the existing `localDate(instant, timeZone)`.
- **Domain:**
  - `completeTask` and `uncompleteTask` learn repeating tasks.
  - `createTask` and `updateTask` accept `recurrence`.
  - A new `settings.ts` handles time zone and week start.
  - `Ctx` gains `weekStart`.
  - Progress (XP, level, streak, trophies) is **derived** by grouped queries in a new `progress.ts`, and read models in `views.ts` carry it to the screens.
- **UI:**
  - Progress pieces in one `progress.tsx`.
  - A recurrence picker and a completion strip on repeating task rows.
  - New `/active`, `/settings` and `/areas/[id]/trophies` pages, all using M2's `read()` / `act()` / `useMutate` patterns unchanged.

**Tech Stack:** as M2 (Next 16.4 with `cacheComponents`, React 19.3, Drizzle + PGlite tests, Vitest unit/db/dom projects, Playwright desktop + Pixel 7, shadcn radix-nova, Tailwind v4). **No new dependencies.**

## Global Constraints

- **Everything in M2's Global Constraints still holds:**
  - Read the Next docs first (AGENTS.md).
  - `act()` / `read()` only; `requireOwner()` first.
  - `<Suspense>` around runtime reads; no `"use cache"` on owner data.
  - The domain boundary rule; the ≥90% line gate on `src/lib/**` and `src/server/domain/**`.
  - The mockup tokens.
  - The `md` breakpoint.
  - No horizontal scroll at 390px.
  - The existing copy strings.
- **XP per effort (§5.2):** 1→10, 2→25, 3→50, 4→100, 5→200. This already exists as `xpForEffort` in `src/lib/xp.ts`.
- **Level curve (§5.2):** XP needed to reach level *n* = `50 × n × (n − 1)`. Level 2 at 100, level 3 at 300, level 5 at 1,000, level 10 at 4,500. Level 1 at 0 XP.
- **Area XP** = the sum of `xp_awarded` over completions of **live** tasks whose `area_id` is that area. Deleting a task removes its XP, and undoing the delete brings it back. Inbox completions keep `xp_awarded = 0`, and filing never back-awards.
- **Streak (§5.3):** the number of consecutive days, ending today *or yesterday*, with ≥1 completion in the area. Days are owner-local, taken from `task_completions.occurrence_date`, which is written as `localDate(now, settings.time_zone)` at completion. "Best streak" is the best *current* streak across areas. Nothing is stored.
- **Recurrence shape (§4)** stays exactly as `Recurrence` in `src/server/db/goals.ts`: `{freq: "daily"|"weekly", interval, byWeekday?, start, end?}`.
- **Presets (§4):** daily, weekdays, weekly on chosen days; for 1 week (`until = start + 6`), 30 days (`until = start + 29`) or forever (`end: {type: "never"}`).
- **Repeating completion (§5.4):** one row per occurrence, today's occurrence only, XP per completion. Missed occurrences are never stored. Achievement progress counts one-off tasks only; M2's `getAreaBoard` already filters on `recurrence is null`.
- **Quiet completion:** no animation or toast on completing. The numbers just update.
- **Copy:** E2E tests depend on these exact strings.
  - Badge `LV {n}` (aria-label `Level {n}`).
  - Streak `🔥 {n}` (aria-label `{n}-day streak`).
  - Trophies `🏆 {n}` (aria-label `{n} trophies`).
  - Strip chips "active achievements", "due this week", "day best streak", "in Inbox".
  - "Up next"; "Nothing active. Pick from backlog".
  - Headings "Active", "Settings", "Trophies", "Today", "Due soon", "Active achievements".
  - Repeat button `Repeat: {description}`; descriptions "Doesn't repeat", "Daily", "Weekdays", "Weekly on Mon, Thu".
  - Checkbox `Complete {title} for today`.
  - Tabs "Areas", "Active", "Capture", "Inbox", "Settings".

## Review Focus

1. **The owner's day isn't UTC.** A completion at 23:30 local time belongs to that local day. "Today", streaks and the strip all use `settings.time_zone`. Test: Task 3, `completeTask` in `Pacific/Auckland`.
2. **Double-ticking a repeating task**, from a double click or two tabs, must award XP once. The second attempt gets `invalid_state`. Test: Task 3.
3. **A repeating task that isn't due today** (weekly on Mon, today is Tue) can't be completed. The server refuses and the UI disables the checkbox. Tests: Task 3 and Task 6.
4. **An ended repetition** ("for 1 week", now past) is never due and drops out of Active → Today. It stays visible on its achievement with its history and the label "Ended". Tests: Task 2 and Task 4.
5. **XP follows the live tree.** Deleting a task or achievement removes its XP and streak days from the area, and Undo restores them. Test: Task 4.

### Task 2: Recurrence functions, presets and the 4-week strip

**Files:**
- Create: `src/lib/recurrence.ts`, `src/lib/recurrence.test.ts`
- Modify: `src/server/db/goals.ts`. Move the `Recurrence` type into `src/lib/recurrence.ts`, and have `goals.ts` do `import type { Recurrence } from "@/lib/recurrence"` and re-export it, so existing imports keep working.

**Interfaces:**
- Consumes: Task 1's `addDays`, `daysBetween`, `weekdayOf`, `weekStartOf`; `formatDeadline` from `dates.ts`.
- Produces:
  - Occurrence checks:
    - `isDueOn(r: Recurrence, date: string): boolean`
    - `occurrencesBetween(r: Recurrence, from: string, to: string): string[]` (both ends inclusive)
    - `hasEnded(r: Recurrence, today: string): boolean` (no occurrence on or after `today`)
  - Presets:
    - `type RepeatPreset = "daily" | "weekdays" | "weekly"`
    - `type RepeatSpan = "week" | "month" | "forever"`
    - `buildRecurrence(p: { preset: RepeatPreset; days?: number[]; span: RepeatSpan }, start: string): Recurrence`
  - `describeRecurrence(r: Recurrence): string`
  - The strip:
    - `type StripState = "done" | "missed" | "due" | "upcoming" | "off"`
    - `type StripDay = { date: string; state: StripState }`
    - `completionStrip(r: Recurrence, done: ReadonlySet<string>, today: string, weekStart: number): StripDay[]` (always 28 days)

**Rules the tests pin:**
- Nothing occurs before `start`.
- **daily:** due when `daysBetween(start, d) % interval === 0`.
- **weekly:**
  - Due when `weekdayOf(d)` is in `byWeekday`, which defaults to `[weekdayOf(start)]`.
  - Also, the number of whole weeks between the Monday-weeks of `start` and `d` must be divisible by `interval`. Weeks are anchored on Monday, independent of settings, so a change of week start can't move occurrences.
- **`until`:** includes the until date.
- **`count`:** due only for the first `count` occurrences.
- **The strip:**
  - Runs from `weekStartOf(today, weekStart) − 21` days, for 28 days.
  - A non-occurrence day is `off`.
  - An occurrence is `done` if it's in the done set; otherwise `missed` before today, `due` today, and `upcoming` after.

- **`completeTask` on a repeating task:**
  - Today is `localDate(ctx.now(), ctx.timeZone)`.
  - It requires `isDueOn(recurrence, today)` and no completion row for today; otherwise `invalid_state`.

  - It returns `{ task, completion }` as now.
- **`uncompleteTask` on a repeating task:** deletes only today's row and records a delete event. `invalid_state` if there is none.
- **Decided here:** settings changes are not written to `change_events`. Settings aren't goal data and undoing a time-zone change has no use.

      - `today: string`
      - `practice: PracticeTask[]`
      - `dueSoon: DueItem[]`
      - `groups: ActiveGroup[]`
  - The `getActive` row types:
    - `PracticeTask = { id; title; effort; recurrence: Recurrence; doneToday: boolean; achievementId; achievementTitle; area: NavArea }`
    - `DueItem = { kind: "task" | "achievement"; id; title; deadline: string; achievementId: string; area: NavArea }`
    - `ActiveGroup = { area: NavArea; achievements: { id; title; deadline: string | null; taskCount: number; doneCount: number; upNext: UpNext }[] }`
    - `NavArea = { id: string; name: string; emoji: string | null }`
  - `getAchievement` also returns `today: string` and `weekStart: number`, and each task gains `recentDone: string[]`. Those are its completion `occurrence_date`s from `addDays(weekStartOf(today, weekStart), −21)` onward.

**Rules:**
- **Up next:** candidates are live tasks in the area's **active** achievements.
- **Due this week:** live, unfinished one-off tasks under a non-done achievement, plus non-done achievements, whose deadline is ≤ the last day of this week (`weekStartOf(today, weekStart) + 6`). Overdue items are included and repeating tasks excluded.
- **Due soon:** the same sources with deadline ≤ `today + 7`, ordered by deadline.
- **Practice:** repeating tasks in active achievements that are due today, whether done today or not.
- **Groups:** areas in their sort order, each with its active achievements in board order. Areas with none are left out.
