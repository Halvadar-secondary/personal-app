# M2 Core UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner can run their goals from the app on desktop and phone. They can see their areas, open an area as a board (desktop) or grouped list (phone), and open an achievement as a task checklist. They can capture anything from anywhere and file it from the Inbox. Every change feels instant, rolls back with a message if the server refuses it, and deletes offer an Undo toast.

**Architecture:**
- **Reads:** pages are Server Components. They read through a small `read()` helper: owner check, then `runAction` on a domain read. The read sits inside `<Suspense>`, because `cacheComponents` is on and the data is per-request.
- **Writes:** each change is a Server Action in `src/server/actions/*.ts`, and every one goes through one `act()` helper. `act()` checks the owner, runs the domain action with actor `ui` and a known batch id, then calls `refresh()` from `next/cache`, so the re-rendered page comes back in the same round trip. It returns a small serialisable `Result`.
- **Optimistic UI:** client components apply changes with React's `useOptimistic` inside a transition. Whatever the outcome, the optimistic state is replaced when the transition ends. On success it gives way to the refreshed server data, and on failure it reverts and an error toast appears.
- **Drag:** `dnd-kit` with pointer, touch and keyboard sensors. Pure functions in `src/lib/placement.ts` turn a drop into `{status?, afterId, beforeId}`.
- **No new domain write actions.** M2 adds three read models and one `ActionDeps` field.

**Tech Stack:** Next.js 16.4 (App Router, `cacheComponents`, Server Actions, `refresh`), React 19.3 `useOptimistic`, Tailwind v4 + shadcn/ui (radix-nova), **new:** `@dnd-kit/core` 6, `@dnd-kit/sortable` 10, `@dnd-kit/utilities` 3, `sonner` (via `shadcn add sonner`). **New dev:** `jsdom`, `@testing-library/react`, `@testing-library/user-event`.

## Review Focus

1. **The server refuses a change the UI already showed**, for example an achievement deleted in another tab, or an undo conflict. The UI must revert and show the domain message. It must never keep the optimistic state. Pinned in Task 4 (`use-mutate.dom.test.tsx`: rejected result reverts and toasts) and Task 2 (messages per code).
2. **Typing `c` in a text field**, such as a task title or the capture field itself, must not open capture. Pinned in Task 8 (`capture.dom.test.tsx`).
3. **Odd drops:**
   - onto an empty column
   - onto the card itself
   - back to the start position
   - the last card into the first slot

   Each must produce the right `{status, afterId, beforeId}`, or a no-op that sends nothing. Pinned in Task 3 (`placement.test.ts`).
4. **A Server Action called directly by a non-owner** (it's a public POST endpoint) must be rejected before the database is touched. This holds for every export, including ones added later. Pinned in Task 2 (`actions.sweep.test.ts`, which globs every module).
5. **Pages for missing or deleted ids**, such as an old link to a deleted achievement or someone else's id, must 404 rather than throw a 500. **Phone layouts** must not scroll sideways. Pinned in Task 2 (`read()` maps `not_found`) and Task 9 (E2E: deleted achievement URL → 404; `scrollWidth <= clientWidth` on every page in the phone project).

### Task 2: The UI adapter: `act`, `read`, and the Server Action modules

**Files:**
- Create: `src/server/actions/run.ts`, `src/server/actions/{areas,achievements,tasks,categories,inbox,history}.ts`
- Test: `src/server/actions/run.db.test.ts`, `src/server/actions/actions.sweep.test.ts`
- Modify: `vitest.config.ts` (the `unit` project includes `src/server/actions/*.sweep.test.ts`; the existing globs already pick it up, so just verify)

**Interfaces:**
- Consumes: `runAction`, `ActionDeps.batchId`, `DomainError`, `requireOwner`, `getDb`, `refresh` (`next/cache`), `notFound` (`next/navigation`).
- Produces:
  - Types:
    - `type Result<T = undefined> = { ok: true; data: T; batchId: string } | { ok: false; code: DomainErrorCode; message: string }`
  - Helpers in `run.ts`:
    - `makeAct(env: { owner: () => Promise<{ id: string }>; db: () => Db; refresh: () => void })` returns `act<S, O, T>(action, input, pick?: (o: O) => T): Promise<Result<T>>`.
    - `act` is exported as `makeAct({ owner: requireOwner, db: getDb, refresh })`.
    - `makeRead(env)` returns `read<S, O>(action, input): Promise<O>`, which maps `not_found` to `notFound()`. `read` is exported the same way.
    - `messageFor(code: DomainErrorCode): string`.
  - Server Actions (each `async (input) => Result<…>`):

    | Module | Exports |
    |---|---|
    | `areas` | `createAreaAction` → `{id}`, `updateAreaAction`, `reorderAreaAction`, `deleteAreaAction` |
    | `achievements` | `createAchievementAction` → `{id}`, `updateAchievementAction`, `moveAchievementAction`, `deleteAchievementAction` |
    | `tasks` | `createTaskAction` → `{id}`, `updateTaskAction`, `moveTaskAction`, `completeTaskAction`, `uncompleteTaskAction`, `deleteTaskAction` |
    | `categories` | `createCategoryAction` → `{id}`, `setTaskCategoriesAction` |
    | `inbox` | `captureAction` → `{kind,id}`, `fileAchievementAction`, `fileTaskAction` |
    | `history` | `undoAction` (takes `{batchId}`) |

    Inputs are the domain schemas' input types (`z.input<typeof x.input>`).

**Behaviour:**
- `act()` does these in order:
  1. `await env.owner()`. A redirect, `notFound`, or other throw propagates.
  2. Create a `batchId`.
  3. `runAction({db, ownerId, actor: "ui", batchId}, …)`.
  4. On success, `env.refresh()` and return `{ok: true, data: pick?.(o), batchId}`.
  5. On a `DomainError`, return `{ok: false, code, message: messageFor(code)}` and **don't** refresh.
- Any other error is rethrown, so Next masks it.

Messages for `messageFor`:

| Code | Message |
|---|---|
| `invalid_input` | "That doesn't look right. Check what you entered." |
| `not_found` | "That item no longer exists. Refresh to see the latest." |
| `invalid_state` | "That's already been done." |
| `conflict` | "Something changed since. Refresh and try again." |
| `already_undone` | "That was already undone." |
